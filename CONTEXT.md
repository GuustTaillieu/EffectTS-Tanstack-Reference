# Project Context: Full-Stack Music Quiz (Effect 4.0 + TanStack Start + Expo React Native)

> **Purpose of this Document**: This file serves as the complete, authoritative architectural and operational context for any LLM (or developer) starting a fresh session. It captures the project history, design decisions, monorepo structure, Effect 4.0 specifics, TanStack Start patterns, React Native integration lessons, and the current codebase status.

## 1. Project Overview & Vision

A full-stack, real-time multiplayer **Spotify Music Quiz** application built as a modern **pnpm monorepo**.
- **Host Screen (Web)**: Runs on a big screen / desktop browser using **TanStack Start**, managing the Spotify audio player, displaying questions, and streaming real-time game events to all players via Server-Sent Events (SSE).
- **Player Controller (Mobile)**: Built with **Expo SDK 58 (React Native)** using Expo Router. Players join rooms with a room code, receive real-time round updates, and buzz in / submit guesses from their mobile phones.
- **Pure Core Logic**: All domain logic, error schemas, event streams, and service contracts are powered by **Effect 4.0 LTS** (`effect: ^4.0.5`), keeping business logic decoupled, type-safe, and testable.

## 3. Key Architectural Patterns & Hard-Learned Lessons

### A. Effect 4.0 LTS (`effect: ^4.0.5`) Specifics
1. **No `@effect/platform` v3**: Do not install `@effect/platform` from npm alongside `effect: ^4.x`. It causes dual-version symbol collisions (`[Effect.TypeId]`). Instead, use standard Web `Request`/`Response` and `Stream.toReadableStream` directly.
2. **Decoding**: In Effect 4, `Schema.decodeUnknown` is replaced by:
   - Synchronous: `Schema.decodeUnknownSync(Schema)(data)`
   - Effect-returning: `Schema.decodeUnknownEffect(Schema)(data)`
3. **Cause Extraction**: `Cause.findError(exit.cause)` returns a `Result`:
   ```typescript
   const errResult = Cause.findError(exit.cause)
   if (Result.isSuccess(errResult)) {
     const error = errResult.success // Note: .success, NOT .value
   }
   ```
4. **Tagged Errors**: Always declare domain errors using `Schema.TaggedError`:
   ```typescript
   export class LobbyNotFoundError extends Schema.TaggedError<LobbyNotFoundError>()(
     "LobbyNotFoundError",
     { lobbyCode: Schema.String }
   ) {}
   ```
   *Benefit*: In Effect, `Effect.catchTag("LobbyNotFoundError", (err) => ...)` checks the `_tag` property. It matches plain JSON objects returned over HTTP with `{ _tag: "LobbyNotFoundError", ... }` without needing manual class instantiation.

---

### B. End-to-End Type Safety Contract Pattern (Zero Manual Client Mapping)
**The Problem Solved**: Manual client mapping (`if (err._tag === "LobbyNotFoundError") ...`) causes silent drift where new errors (like `UsernameTakenError`) are forgotten and swallowed into generic network errors.

**The Solution**:
1. **Contract as Single Source of Truth** ([`shared/domain/contract.ts`](file:///home/gustavo/Documents/projects/learn-effect/shared/domain/contract.ts)):
   ```typescript
   export interface QuizApiContract {
     joinLobby: {
       readonly path: "/api/lobby/join"
       readonly input: JoinLobbyInput
       readonly success: Lobby
       readonly errors: LobbyNotFoundError | LobbyFullError | UsernameTakenError
     }
     submitGuess: {
       readonly path: "/api/game/guess"
       readonly input: SubmitGuessInput
       readonly success: void
       readonly errors: GameNotFoundError
     }
   }
   ```
2. **Generic Effect RPC Dispatcher** ([`shared/client-sdk/index.ts`](file:///home/gustavo/Documents/projects/learn-effect/shared/client-sdk/index.ts)):
   - Connects to the endpoint and deserializes the server's `{ _tag: "Failure", error }` payload.
   - Directly fails into Effect's failure channel with `Effect.fail(raw.error)`.
   - The TypeScript return type is dynamically derived:
     `Effect.Effect<QuizApiContract[K]["success"], QuizApiContract[K]["errors"] | NetworkError>`
3. **Consumption in UI (Mobile & Web)**:
   ```typescript
   quizClient.joinLobby(input).pipe(
     Effect.catchTags({
       UsernameTakenError: (err) => Effect.fail(new Error(`Nickname "${err.username}" taken!`)),
       LobbyNotFoundError: (err) => Effect.fail(new Error(`Lobby "${err.lobbyCode}" not found!`)),
       LobbyFullError: (err) => Effect.fail(new Error(`Lobby is full (max ${err.maxPlayers})!`)),
       NetworkError: (err) => Effect.fail(new Error(`Connection failed: ${err.message}`))
     })
   )
   ```
   *TypeScript strictly enforces all tags and types with zero `any`.*

### C. TanStack Start Serialization & `WireError<E>`
TanStack Start uses Seroval for Server Function RPC. Seroval throws errors if functions, class methods, or symbols exist in the returned data:
- `WireError<E>` in [`apps/web/src/server/effectFn.ts`](file:///home/gustavo/Documents/projects/learn-effect/apps/web/src/server/effectFn.ts) strips phantom covariance symbols (`[Effect.TypeId]`, `.pipe`, `cause`) so TanStack Start's `ValidateSerializable` passes with 0 errors.
- `runServerEffect` cleans return values via `JSON.parse(JSON.stringify(exit.value))`.
- `clientEffect` wraps `createServerFn` to return native `Effect<A, WireError<E>>`, allowing `.pipe(Effect.catchTag(...))` directly in React components.

### D. Expo SDK 58 React Native in a Monorepo
1. **Single React Version**: All workspaces MUST use the exact same React version (`"react": "19.3.1"`). Having `19.3.0` in mobile and `19.3.1` in web causes pnpm to create two `@tanstack/react-query` context instances, throwing `[Error: No QueryClient set, use QueryClientProvider to set one]`.
2. **Metro Monorepo Config** ([`apps/mobile/metro.config.js`](file:///home/gustavo/Documents/projects/learn-effect/apps/mobile/metro.config.js)):
   ```javascript
   config.watchFolders = [monorepoRoot];
   config.resolver.nodeModulesPaths = [
     path.resolve(projectRoot, "node_modules"),
     path.resolve(monorepoRoot, "node_modules"),
   ];
   config.resolver.extraNodeModules = {
     react: path.resolve(projectRoot, "node_modules/react"),
     "react-dom": path.resolve(projectRoot, "node_modules/react-dom"),
     "@tanstack/react-query": path.resolve(projectRoot, "node_modules/@tanstack/react-query"),
   };
   ```
3. **Explicit QueryClient**: `useEffectMutation` accepts `queryClient?: QueryClient` to bypass any context boundary isolation quirks between packages.
4. **LAN / Network Binding**:
   - `apps/web/vite.config.ts` has `server: { host: true }` so Vite listens on `0.0.0.0` (`http://10.0.0.32:5173/`).
   - `apps/mobile/src/lib/api.ts` auto-detects the host IP using `Constants.expoConfig?.hostUri` (which contains `10.0.0.32:8081` on mobile), so mobile automatically targets `http://10.0.0.32:5173`.
   - Android Emulator loopback alias: `10.0.2.2:5173` or `adb reverse tcp:5173 tcp:5173`.
